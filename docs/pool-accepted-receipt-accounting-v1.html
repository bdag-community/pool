Pool Accepted-Receipt Accounting v1

Status: additive local accounting materialization for the durable submission journal. This extension supersedes the journal document's economic exclusion for the combined source head only. Its policy identifier is PPLNS-DISCOVERY-CUT/v1.

Discovery boundary

When a valid block candidate is discovered, Pool takes one locked PPLNS snapshot. A normal valid share is inserted before that snapshot; an otherwise valid low-difficulty block remains excluded under the existing policy. Pool freezes the candidate, fee inputs, total work, and sorted per-miner credit lines into a canonical digest.

Durability boundary

The complete immutable intent commits in the same PostgreSQL transaction as the candidate and initial submission state, before any HTTP request. Equal replay must match the intent digest. Missing or variant intent data latches a conflict and fails closed.

Accepted-receipt consumer

Only a matching immutable accepted receipt and intent may create accounting rows. One transaction locks them, records one effect marker keyed by candidate ID, inserts one legacy block keyed by the persisted share PoW hash, inserts the persisted sorted credit lines, and commits all-or-none. Repetition, concurrency, restart, and commit-acknowledgement loss converge by reading the effect marker. Unexpected pre-existing legacy rows are conflicts; they are never adopted.

Startup and runtime

The versioned SQL migration must be installed by the operator. Pool verifies schema bindings, drains and verifies accepted-but-unapplied receipts before opening Stratum, and continues bounded reconciliation while running. A prepared orphan accepted during the readiness scan is drained before the listener opens.

Claim ceiling

This proves durable discovery-time intent and exactly-once local creation of the corresponding legacy block and per-miner credit rows. It does not prove or perform canonical maturity, wallet transactions, payouts, historical backfill, live deployment, or release-tuple qualification.
