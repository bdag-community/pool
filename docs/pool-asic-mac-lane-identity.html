Pool ASIC MAC Lane Identity

Repo: poolBranch: jeremy-devInvariant: MAC-only local ASIC lanes

The Stratum pool must distinguish physical ASIC work lanes by hardware identity instead of collapsing multiple ASICs behind one wallet, worker, session, or transient IP observation.

Why This Exists

Several local ASICs mine to the same payout wallet. Wallets are payout identities, not physical miner identities. When operational views or recovery windows group shared-wallet clients as one lane, the pool and dashboard can undercount the local pool, hide failed ASICs, or attribute work to one device that actually came from several devices.

Identity Order

IdentityUseRule
mac:<normalized-mac>Physical LAN ASIC lane identityRequired for configured/local ASIC LAN routes. Resolved from stack overrides or the host neighbor table.
unknownUnresolved local ASIC routeUsed for configured/local ASIC LAN routes when the MAC is unavailable. These routes stay unattributed until the MAC is collected.
ip:<remote-host>Remote Stratum laneUsed only for remote Stratum clients outside BDAG_ASIC_LAN_CIDRS; never for physical LAN ASICs.
Stratum session/extranonceProtocol connection identityUsed only for non-MAC fallback recovery uniqueness.
Wallet usernamePayout attributionNever a durable ASIC lane; multiple ASICs may intentionally share one wallet.

Implementation

On each accepted Stratum connection, the pool stores addr, remote_host, asic_mac, and lane_id on the client. MAC resolution checks POOL_ASIC_MAC_OVERRIDES first, then the Linux ARP table from /proc/net/arp or POOL_ASIC_ARP_TABLE_PATH. The pool also reads BDAG_ASIC_LAN_CIDRS so it can reject IP-lane fallback for physical LAN ASIC routes. The /health/job-state endpoint exposes these fields per client, and expired-job global recovery uses the MAC lane before session, extranonce, remote-IP, username, or raw address.

Deployment Notes

Containers may not see LAN neighbor entries depending on Docker network mode. Stack deployments must provide BDAG_ASIC_LAN_CIDRS and should provide POOL_ASIC_MAC_OVERRIDES from the miner registry when host ARP visibility is not guaranteed. This keeps the pool code MAC-only for LAN ASICs without depending on Codex or a human to infer lanes from dashboard logs.

Regression Guard

Do not remove or weaken the tests covering resolveASICMACForRemote, clientLaneIdentity, snapshotClientJobHealth, and expiredJobClientKey. Those tests are the durable guard against returning to wallet-first or IP-only ASIC lane behavior.
