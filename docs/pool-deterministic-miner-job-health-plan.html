Pool Deterministic Miner Job Health

Repo: poolBranch: feature/pool-deterministic-miner-job-healthRisk: observe-only

This task turns Stratum miner/job state into explicit source-level signals, so dashboards and watchdogs do not infer pool health from log text or indirect submit-error bursts.

Problem

The pool currently has good counters for accepted shares, rejected shares, backend routing, and recovery actions. It does not expose a deterministic snapshot of whether connected miners have a current, non-stale, non-invalidated job.

Goal

Expose passive aggregate metrics and an internal JSON health endpoint that show miner readiness, current-job freshness, accepted-job pressure, and clear reason codes.

Non-Goal

No mining behavior, job broadcast policy, VarDiff policy, backend routing, ASIC configuration, Docker services, or live stack state changes in this PR.

Signals To Add

Implementation Notes

  • Use existing globals: clients, acceptedJobs, lastSeq, lastBroadcastTime, and per-client currentJob.
  • Expose per-client ASIC identity as remote_host, asic_mac, lane_id, and lane_identity_source. Configured/local ASIC LAN lanes are MAC-only; remote Stratum clients outside BDAG_ASIC_LAN_CIDRS may use IP lanes. Payout wallet usernames are not lane identities.
  • Keep Prometheus metrics aggregate-only to avoid high-cardinality miner labels.
  • Sort JSON client rows for deterministic dashboard output and predictable tests.
  • Expose the endpoint on the existing metrics HTTP server, alongside /metrics, so no new process or port is required.

Definition Of Done

  • Design committed before behavior changes.
  • New endpoint and gauges are passive and source-only.
  • Unit tests cover healthy, missing-current-job, stale, invalidated, and expired-current-job cases.
  • Focused tests pass: go test ./internal/pool/server -run 'TestPoolJobHealth|TestJobHealth' -count=1.
  • Package tests pass for ./internal/pool/server.
