Pool Durable Submission Journal v1

Status: the Pool-only non-economic durable submission boundary for POOL-DURABLE-SUBMISSION-JOURNAL/v1. This document is limited to the tested source envelope and makes no Core, accounting, or release claim.

Boundary

A frozen 185-byte header and exact four-byte extraNonce2 are committed with a prepared RPC attempt before HTTP. HTTP is outside the PostgreSQL transaction; reconciliation reuses only the committed request bytes.

Acceptance

Only a strict structured accepted or already_accepted outcome with the matching Core block hash may create one immutable accepted-submission receipt. Ambiguous outcomes remain pending; identity and terminal contradictions append evidence and latch a global conflict.

Economic boundary

The journal does not write block_submissions, blocks, credits, payouts, maturity, or payout state. Accepted receipts are inputs for a separately authorized accounting packet.

Operations

PostgreSQL is required. The binary verifies, but does not run, the versioned migration. There is one reconciler worker, bounded response evidence, and no unsafe journal-disabled mode.
