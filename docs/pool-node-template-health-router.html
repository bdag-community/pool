Pool Node Template Health Router

The pool can consume the single configured node's mining-template health RPC and use it to pause unsafe template or submit work while keeping template-fetch and submit-path checks as fallback signals. This adds a clean source-level contract for node readiness.

Opt-in No production deployment in this commit Consumes getTemplateHealth Reduces watchdog guessing

What Changed

Health Probe

The pool can call getTemplateHealth on the configured node at a low rate. The call is disabled by default until patched corechain nodes are deployed.

Router Input

The router records mineable_now, submit_ready, template age, template sequence, main order, and reason codes in each backend state.

Automatic Fallback

If the selected node reports it is not mineable or not submit-ready, the router marks it unhealthy and keeps template or submit recovery on the single configured node.

Rolling Compatibility

If a backend returns method-not-found, the pool marks node health unsupported but does not fail closed. Existing template and submit signals remain authoritative.

False-Negative Hysteresis

Transient node_syncing, timeout, or retryable health failures are advisory while the node still has fresh template evidence. They only fail routing after repeated consecutive samples.

Why It Matters

Most mining losses we observed were not caused by raw CPU shortage. They were caused by miners receiving work from a backend that was technically reachable but operationally poor for mining: stale template, sync ambiguity, submit path not ready, or peer/template state behind the useful DAG frontier. This feature gives the pool a direct node-level signal before the external watchdog has to infer failure from logs, stale shares, and submit errors.
