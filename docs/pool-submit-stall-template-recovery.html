Pool Submit Stall Template Recovery

This feature makes the pool binary detect a zero-success block-submit stall and repair its own job/template state before the watchdog has to restart the pool.

Pool-only change Feature flagged Router-aware Clean Stratum notify Prometheus metric Conversion ratio guard

Problem

Observed Failure

Miners can keep submitting block candidates while the node rejects every candidate as duplicate, overdue, expired, or stale. Hashing continues, but monetized accepted blocks drop to zero.

Why The Watchdog Was Late

The external watchdog sees the failure after the fact and restarts the pool. That works, but costs minutes of degraded mining.

Root Pool Weakness

The old refresh path cleared the template cache, but a same-template refresh could still be sent with clean_jobs=false, leaving ASICs free to continue work against a poisoned job.

Recovery Design

Step What happens Why it helps
Detect zero-success failure window The pool tracks block-candidate failures since the last successful node submit. Recovery is based on failed monetization, not normal share noise.
Classify dangerous reasons RPC stale/overdue/expired errors, RPC duplicate errors, local duplicate block, and global duplicate block failures contribute to the stall detector. These are the signatures seen when the pool is working against an unusable job/template path.
Track poor candidate conversion The pool also tracks accepted versus failed block-candidate outcomes across a rolling window, so a few intermittent accepted blocks no longer hide a mostly broken template/backend path. This closes the failure mode observed on 2026-05-17 where accepted blocks were not zero, but miner-normalized block conversion collapsed for more than two hours.
Refresh the configured node If the RPC router detects a submit stall, the current node is marked submit-stall and the pool forces a clean template refresh on the configured node. A stuck node should not hold the pool when the next refresh can clear the poisoned job state.
Force clean template refresh The current template key is invalidated so even an identical template forces clean_jobs=true. ASICs abandon the poisoned job instead of continuing to submit doomed candidates.
Adopt direct-broadcast parents Any direct recovery broadcast records the template parent in the pool's current-parent state before miners submit against it. Recovery jobs are not incorrectly rejected as locally stale after a forced clean refresh.
Invalidate accepted jobs Existing accepted job records are marked stale and invalidated just before broadcasting the recovery job. Late submits against old jobs are rejected locally instead of wasting node RPC capacity.

Validation

Unit Tests

Submit recovery tests verify threshold behavior, accepted-submit reset behavior, and stale/duplicate fast triggers.

Node Health Test

A node-health test verifies that submit-stall recovery marks the configured node unhealthy and forces a fresh template path before miners continue.

Operational Metric

pool_submit_stall_recoveries_total{action,reason} and pool_template_conversion_stall_recoveries_total{action,reason} record started recoveries and clean refreshes.

pool_template_conversion_stall_window_candidates{kind} and pool_template_conversion_stall_failure_ratio expose the rolling health window used by the new guard.
